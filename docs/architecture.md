# 아키텍처 결정 기록

## 결론: API 기반 멀티모달 LLM을 보조 분석기로 사용

초기 버전에서 자체 LLM을 학습하지 않는다. 범용 비전 언어 모델 API를 호출하되, 주문 결정권은
규칙 기반 전략과 리스크 엔진에 둔다.

자체 모델은 대규모로 라벨링된 차트·시장상태·미래수익 데이터, GPU 운영, 재학습과 모델 모니터링이
필요하다. 초기 프로젝트에는 비용이 크고 과적합 및 데이터 누수 위험도 높다. API는 빠르게 평가를
시작하고 모델을 교체하기 쉽다. 단, 같은 입력에서도 응답이 달라질 수 있으므로 신호 생성의 유일한
근거로 사용하지 않는다.

## 판단 흐름

```text
Bybit V5 market data
        |
        v
validated OHLCV + funding + open interest
        |
        +--> deterministic indicators/regime/strategy ----+
        |                                                  |
        +--> canonical chart image + numeric context --> LLM reviewer
                                                           |
                                                           v
                                                signal consensus gate
                                                           |
                                                           v
                                          deterministic risk engine
                                                           |
                                                           v
                                      paper/testnet execution adapter
```

LLM에는 차트 이미지만 보내지 않는다. 캔들 이미지 렌더링 방식은 고정하고, OHLCV 요약, EMA, RSI,
MACD, Bollinger Bands, ATR, 거래량, 펀딩비, 미결제약정, 시간대와 데이터 종료 시각을 함께 전달한다.
출력은 `LONG | SHORT | NO_TRADE`, 신뢰도, 무효화 가격, 근거 코드로 제한한다.

## 중요한 연구 원칙

- 이미지의 패턴 인식 능력은 가정하지 않고 별도 평가셋으로 검증한다.
- 수익률 라벨은 입력 캔들 이후 구간으로 만들며 미래 데이터 누수를 차단한다.
- 수수료, 펀딩비, 슬리피지, 주문 미체결을 백테스트에 포함한다.
- 랜덤 분할 대신 시간 순서 기반 워크포워드 검증을 사용한다.
- LLM 포함/제외 전략의 순수 기여도를 동일 기간에서 비교한다.
- 기대값, 손익비, MDD, Sharpe/Sortino, 거래 횟수와 국면별 성과를 기록한다.

## 모델 운영 권장안

초기 평가에서는 비용 효율적인 비전 모델을 기본값으로 사용하고, 애매한 사례만 더 강한 모델로
재검토하는 2단계 라우팅을 고려한다. 모델 ID와 프롬프트 버전은 모든 판단 로그에 저장한다.
API가 실패하거나 시간 제한을 넘으면 신규 포지션을 열지 않는다.

## 보안과 실행 경계

- Bybit API 키는 거래 전용, 출금 권한 없음, IP 화이트리스트 적용
- 로그와 예외에 키·서명·전체 인증 헤더를 남기지 않음
- 테스트넷과 실거래 설정 및 자격 증명을 분리
- 실거래는 단일 환경변수만으로 켤 수 없도록 추가 승인을 요구할 예정
- 보호 손절 주문 확인 전에는 진입 주문을 완료 상태로 간주하지 않음
